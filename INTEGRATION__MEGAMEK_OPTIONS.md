# MegaMek game options, sorted for the Combat Lab

*Made 2026-11-20 from MegaMek's own source (`GameOptions.java`, `OptionsConstants.java`, and the options message file on its `master` branch; MegaMek is GPL v3+, CREDITS.md). Names and one-line meanings are MegaMek's. **The sorting is Claude's first pass: it is Daniel's to change.***

**How I sorted** (Daniel, 2026-11-20: "Not needed, want, and can implement"):

- **Already built**: we have a switch for it.
- **Can implement**: a rule between mechs whose text is in our rules library (TO: Advanced Rules, TO:AUE or the Core Rulebook), or that needs no book text (engine-only logic). It could become a switch in the OPTIONAL RULES section now.
- **Want**: relevant to the simulator but not buildable yet: either my search of the library found no rule text (so the book or MegaMek's source has to be read first), or it needs a system the engine does not have (quirks, pilot abilities, Edge, sensors, minefields, a terrain-state layer).
- **Not needed**: lobby and display settings, multiplayer, fog of war, infantry, vehicles, VTOLs, ProtoMeks, aerospace, nukes, and unofficial oddities.


**252 MegaMek options** (Already built: 5 · Can implement: 64 · Want: 53 · Not needed: 130). Duplicate: MegaMek lists `protos_move_even` twice.

# Pruning OUR options list (a proposal: nothing here has been removed yet)

The Options tab lists **126** settings, of which **74** are live in the Rust engine. Growing it with the MegaMek rules above needs a list people can read, so I propose these four cuts. Each is a change to `tools/make_options_registry.py` (which writes `options.json`); none touches the engine, and every setting keeps its value in `engine/defaults/config.json`.

1. **Hide the "Technical and debugging" folder (26 settings).** They are Python-era switches (compiled hot loops, GIF / heat-map rendering, test-only verifiers, stats folders) or are owned by the Lab's own pages (replays, saved states, statistics). Only `VERBOSE` is live.
